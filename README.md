# 屏幕点击宏（AutoClick）

一个通用的 Android“屏幕自动点击 / 宏”工具：在屏幕上标记多个固定坐标的点击点，把它们按顺序编排成“方案”，通过悬浮控制条一键执行。
典型用法：游戏出装界面里“卖掉 A 装备再买 B 装备”，需要按顺序点击若干固定位置。

技术栈：Kotlin、Jetpack Compose（Material 3）、Gradle（Kotlin DSL）、DataStore + kotlinx.serialization，`minSdk 26`，`targetSdk 34`。

> **风险提示**：在联网游戏或其他在线服务中使用自动化/连点工具，可能违反游戏用户协议并导致账号警告、封禁等处罚，后果由使用者自行承担。
> 本应用只通过无障碍手势派发点击：不需要 root，不读取屏幕内容，不注入、不修改任何应用的内存或文件，也不做任何反作弊规避或游戏检测。

## 功能

- **无障碍点击**：`AccessibilityService` + `dispatchGesture`，支持普通点击和长按。服务配置里没有声明事件监听，也不请求窗口内容。
- **悬浮控制按钮**（`SYSTEM_ALERT_WINDOW`）：一个可拖动的圆形按钮，待机时是“开始”三角，执行/倒计时中变为红色“停止”方块，两种状态大小不变，不含方案选择和关闭按钮：执行首页选中的方案，关闭在应用内操作。大小（50–150%）、透明度（20–100%）、待机颜色（预设 + 自定义十六进制）在首页“悬浮按钮外观”里设置并实时生效。
- **取点模式**：全屏半透明覆盖层，点哪里就记录该处的屏幕绝对坐标并显示编号标记（并用细线连接顺序）。
  - 默认“暂停”（触摸穿透），先切换到目标界面再点“开始取点”；面板可拖动，支持“撤销”。
- **方案管理**：新建 / 重命名 / 复制 / 删除；每个方案是有序步骤列表，步骤 = 坐标 (x, y) + 点击后延迟（毫秒）+ 可选长按时长；可编辑、上移/下移、删除、手动添加；整个方案可设循环次数（1 表示只执行一次，也可选“无限循环”）。数据以 JSON 存在 DataStore。
- **一键执行**：首页选中方案 → 悬浮条点开始；执行前有可设置（0–30 秒）的倒计时，屏幕中央显示数字（大小/透明度跟随悬浮条设置）；任何时候可点“停止”。
- **首次使用引导**：首次启动展示用途、权限说明和风险提示（须点击确认）；首页的授权卡片引导开启悬浮窗权限与无障碍服务（含 Android 13+“受限制的设置”提示）。
- **屏幕尺寸校验**：坐标为绝对像素，方案在首次取点时记录当时的屏幕尺寸。当前尺寸与记录不一致（含横竖屏旋转）时，列表与编辑页会提示，悬浮条拒绝执行，取点也会拒绝；确认坐标仍适用时可在编辑页“按当前屏幕校准”。

## 构建

需要 JDK 17+（已用 JDK 21 验证）和 Android SDK（`platforms;android-34`、`build-tools;34.0.0`）。

```bash
# 指定 SDK 位置（二选一）
export ANDROID_HOME=$HOME/android-sdk          # 方式一：环境变量
echo "sdk.dir=$HOME/android-sdk" > local.properties   # 方式二：local.properties

./gradlew assembleDebug        # 产物：app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # 运行单元测试
```

没有 Android Studio 时可用命令行工具安装 SDK：

```bash
mkdir -p $HOME/android-sdk/cmdline-tools
# 下载 commandlinetools-linux-*_latest.zip 并解压为 $HOME/android-sdk/cmdline-tools/latest
yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
```

## 安装

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 授权与使用步骤

1. 打开应用，阅读“使用前必读”（用途、权限、风险提示），点“我已阅读并理解风险，继续”。
2. 首页“授权”卡片：
   - **悬浮窗权限**：点“去授权”，在系统页允许“显示在其他应用上层”。
   - **无障碍服务**：点“去开启”，在系统无障碍设置中找到“屏幕点击宏”并开启。
     若开关为灰色或提示“受限制的设置”（Android 13+ 且通过安装包安装时常见）：在应用信息页右上角菜单选择“允许受限制的设置”，再回来开启。
3. 点“新建方案”，进入方案编辑页：
   - 点“取点”：应用会收起并出现取点面板。先切换到目标界面（此时触摸穿透），再点面板上的“开始取点”，依次点击要点击的位置；点“撤销”可删除最后一个，点“完成”结束。
   - 回到应用，按需调整每步的**点击后延迟**、**长按时长**、顺序，设置**循环次数**。
4. 首页点“显示悬浮条”，切到目标应用，把悬浮条拖到不会遮挡点击点的位置。
5. 在首页把要用的方案“设为悬浮条当前方案”，需要时调整“悬浮按钮外观”；切到目标应用后点悬浮按钮（▶）开始：倒计时结束后按顺序执行；随时点同一个按钮（■）中止。

注意：

- 执行期间如果你自己触摸屏幕，系统可能取消正在派发的手势，方案会中止并提示。
- 方案在尺寸与记录不一致时不会执行（例如横竖屏切换后），请旋转回原方向，或确认后“按当前屏幕校准”。
- 悬浮条以前台服务运行，通知栏有一条常驻通知，可从通知里“关闭悬浮条”。

## 项目结构

```
app/src/main/java/com/autoclick/macro/
├── model/      Plan / Step / ScreenSize 与纯 Kotlin 的方案逻辑（PlanLogic.kt）
├── data/       JSON 编解码（Codec）与 DataStore 持久化（PlanStore）
├── engine/     MacroRunner：倒计时、循环、延迟、停止（与点击实现解耦，可单测）
├── service/    ClickAccessibilityService（dispatchGesture）与 OverlayService（前台服务）
├── overlay/    悬浮条、取点覆盖层、倒计时覆盖层（原生 View + WindowManager）
└── ui/         Compose 界面：首页、方案编辑、说明页、对话框
app/src/test/   单元测试
```

## 测试与验证情况

自动化（在云环境里真实运行）：

- `./gradlew assembleDebug`、`./gradlew testDebugUnitTest`、`./gradlew lintDebug`。
- 单元测试覆盖：方案/步骤逻辑（增删改排序、屏幕尺寸校验、循环与耗时、方案列表操作、数据清洗）、JSON 序列化（往返、未知/缺失字段、损坏数据）、`MacroRunner`（虚拟时间下的倒计时、延迟、循环、无限循环、停止、失败中止）、DataStore 持久化（读写、损坏数据备份）。

**尚未在真机上验证的部分**（单元测试无法覆盖，需要在设备或模拟器上手动确认）：

- 无障碍服务派发的手势在各厂商 ROM、各种游戏里是否被接受（部分应用/游戏可能忽略或拦截无障碍手势，这不在本项目的处理范围内）。
- 悬浮条/取点覆盖层在不同系统版本、刘海屏、折叠屏、分屏/小窗、手势导航下的位置与坐标是否完全一致。
- 厂商 ROM 对悬浮窗、前台服务、后台启动的额外限制，以及 Android 13+“受限制的设置”流程的具体界面。

云环境中尝试过启动 Android 模拟器（x86_64、API 34）做端到端验证，但该沙箱的 `/dev/kvm` 不可用（调用 KVM 接口即崩溃，模拟器进程无法启动内核），因此**没有在模拟器或真机上运行过本应用**。上述 UI、悬浮窗、无障碍点击流程目前只经过编译、lint 与单元测试验证。

## 已知限制

- 只做固定坐标点击（以及长按），不做滑动/拖拽、图像识别或条件判断。
- 坐标绑定屏幕尺寸，不做跨分辨率自动换算（避免误点，宁可拒绝执行）。
- 悬浮条位置不持久化，重启悬浮条后回到默认位置。
